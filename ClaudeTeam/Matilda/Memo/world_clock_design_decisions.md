# 세계 시계 페이지 — 설계 결정 기록

2026-04-30. 첫 실작업. 위치: [web/](../../../web/).

## 스택 결정
- **vanilla HTML/CSS/JS, 빌드 도구 없음.** Admin이 발주에서 명시한 가정. 단일 정적 페이지에 React/Next/Vite를 끼우면 컨벤션이 굳기 전에 방향이 박힌다.
- **서버:** `python3 -m http.server 8080` — 의존성 0.
- **백엔드 호출 없음.** `Intl.DateTimeFormat` + IANA timezone으로 클라이언트 단독 처리.

## 톤 시스템 (낮/노을/밤)
- 4단계: `night` (0–5, 20–24) / `dawn` (5–8) / `day` (8–17) / `dusk` (17–20).
- 카드 배경은 그 도시 **현지 시각**을 따라 보간. 한 화면 안에서 지구의 하루 흐름이 동시에 보이도록.
- 변경 지점: [web/styles.css](../../../web/styles.css)의 `--tone-night/dawn/day/dusk` 변수.
- 베이스: 다크(#0a0c11). 카드만 발광하는 "어두운 라운지의 벽시계" 이미지.

## 타이포 / 디스플레이
- 본문: Inter (200/300/400/500). 시각: JetBrains Mono (200/300).
- 시각은 `tabular-nums` + 라이트 웨이트(200) — 매초 갱신 시 자릿수 흔들림 방지 + 디스플레이 시계 톤.
- 초는 분·시보다 작고 투명도 낮게 — 정보 우선순위.

## 접근성 결정
- `<time>`에 정적 `aria-label="<도시> 현재 시각"`. **live region으로 만들지 않음** — 매초 갱신을 SR에 읽히면 폭주.
- `<ul aria-label="도시별 현재 시각">`로 그룹 의미 부여.
- 다크 배경 위 텍스트 명도 ≥ 4.5:1 (WCAG AA).
- `@media (prefers-reduced-motion: reduce)` — 호버·톤 트랜지션 비활성.
- 모바일 480px 이하 폰트·패딩 축소.

## 의도적으로 하지 않은 것
- 프레임워크/번들러 도입 (스택 가정 준수).
- 사용자 도시 추가/제거 UI (스코프 밖).
- 라이트 모드 (다크가 톤 디자인의 핵심 전제라 라이트로 전환하면 동작 안 함).
- 알람·타이머 기능 (시계 조회 페이지에 한정).

## 회귀 주의 포인트
- `Intl.DateTimeFormat`을 매 tick마다 새로 만들지 말 것 — 캐싱해 둠 (`hmFmtCache` 등). 매초 8개 도시 × N개 포맷터 생성은 비용.
- 도시 추가 시 `CITIES` 배열만 늘리면 되도록 렌더링 로직은 데이터 주도 구조 유지.
- 톤 임계 시각(5/8/17/20)을 사용자가 변경 요청하면 [styles.css](../../../web/styles.css) 변수와 [app.js](../../../web/app.js)의 `tone()` 함수 둘 다 건드릴 필요 없는지 확인 — 현재는 `tone()` 한 곳만 보면 됨.
