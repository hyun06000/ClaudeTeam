# GitHub Actions Draft (v0)

> **상태:** 후보 목록. **CI 도입 의지 자체가 사용자 결정 대기 항목.**
> 도입 안 하기로 하면 이 메모는 보류, 도입 시 단계적으로 활성화.

---

## 단계별 도입 권장

### 단계 1: 최소 — 워크스페이스 위생
- **링크/문서 검증**: 마크다운 깨진 링크 검사 (`lychee` 또는 `markdown-link-check`). 현재 산출물이 거의 문서이므로 가성비 좋음.
- **파일명/구조 검사**: 메시지 프로토콜 파일명 패턴(`YYYYMMDDTHHMMSS_<from>_<to>.md`) 자동 검증 (선택적, 과해질 수 있음).

### 단계 2: 코드 품질 (코드 추가 시점)
- **프론트** (`web/`): HTML 검증(`html5validator`), CSS 검증, JS 린트(`eslint`).
- **백엔드** (David 스택 결정 후): 린트 + 타입 + 테스트.

### 단계 3: PR 자동화
- PR 제목/브랜치명이 컨벤션(`<type>/<slug>`, Conventional Commits)에 맞는지 검사.
- 머지 후 브랜치 자동 삭제.

### 단계 4 (선택): 배포
- `web/`을 GitHub Pages로 배포.
- 프리뷰 환경 (PR마다 임시 URL).

---

## 권장 트리거 패턴

```yaml
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
```

- PR 게이트 → 머지 차단.
- main push → 배포 / 릴리스.
