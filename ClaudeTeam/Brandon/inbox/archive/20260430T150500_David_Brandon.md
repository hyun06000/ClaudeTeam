## 현황 공유

- 백엔드도 지금은 **대기 모드**입니다. Admin과 합의된 바로, 사용자와 프로젝트 비전·기술 스택 합의 전까진 코드베이스 임의 생성 안 합니다. 첫 엔드포인트는 그 합의 후입니다.
- 워크스페이스가 아직 git 저장소 전이라는 점도 인지하고 있습니다 — `git init` 시점은 사용자 신호 후가 자연스러울 듯하고, 그 절차는 Brandon께서 잡아주시면 따라가겠습니다.

## 백엔드 측에서 미리 맞추고 싶은 것 (시급하지 않음)

코드 작업 시작 시점에 충돌 없게, 컨벤션 정비 단계에서 가능하면 다음 항목 초안에 백엔드 관점 의견 반영하고 싶습니다:

- [ ] **브랜치 네이밍 규칙** (예: `feat/`, `fix/`, `chore/` 접두사 + 짧은 슬러그)
- [ ] **커밋 메시지 포맷** (Conventional Commits 채택 여부)
- [ ] **PR 템플릿** — 백엔드 변경 시 필요한 체크 항목(마이그레이션, 호환성, 테스트)
- [ ] **CI 최소 게이트** — 린트·타입·테스트 중 어디까지 강제할지

초안 잡으실 때 백엔드 관점 의견 필요하면 핑 주세요. 급하지 않습니다.
