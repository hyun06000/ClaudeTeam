## 배경

사용자가 Git 협업 규약을 추가했습니다. 컨벤션 문서화는 [ONBOARDING.md §0.5 "Git 협업 규약"](../../../ONBOARDING.md)에 박았고, **실제 구현은 당신 영역**입니다. 다음 세션에 깨어나면 이 메시지를 가장 먼저 처리하세요.

## 합의된 핵심 (사용자 직접 지시)

1. 모든 멤버는 `member/<이름>` 브랜치에서만 작업
2. 머지(`member/*` → `dev`/`main`)는 Brandon 단독 권한
3. 각 비-Brandon 멤버는 git worktree로 작업공간 격리
4. 머지는 메시지 프로토콜로 요청 (GitHub PR 직접 생성 금지, Brandon이 PR화·머지)

## 다음 세션에서 당신이 할 일

### 1단계 — 설계 메모 (코드 전, 합의 우선)

다음 파일들을 [Brandon/Memo/](../../Brandon/Memo/) 아래 초안으로 작성하고 Admin inbox로 검토 요청:

- `branch_strategy.md` — `member/<이름>` 네이밍, `dev` 도입 여부 결정 (지금은 main만 있음. 작은 팀이면 main 직접도 가능 — 본인 판단 + 사용자 결정 받아야).
- `worktree_layout.md` — 워크트리 디렉토리 위치 제안. `<parent>/ClaudeTeam-<이름>/` 형태가 ONBOARDING에 적혀 있으나 실제 경로는 사용자 환경에 맞춰 조정.
- `merge_request_workflow.md` — ONBOARDING의 머지 요청 포맷을 본인 시각으로 다듬어 정식 컨벤션화.
- `setup_script.md` — 멤버별 워크트리·브랜치 셋업을 한 번에 해주는 스크립트 초안 (Bash). 매개변수: 멤버 이름. 실행 결과: `member/<이름>` 브랜치 생성 + `<parent>/ClaudeTeam-<이름>/` 워크트리 생성 + 그 안에 체크아웃.

### 2단계 — Admin 검토 + 사용자 GO

초안 4종이 [Brandon/Memo/](../../Brandon/Memo/)에 올라오면 Admin이 검토하고 사용자에게 가져갑니다. 권한 게이트(워크트리 생성·푸시)가 있을 수 있으므로 사용자 직접 한 줄 GO를 받은 뒤 다음 단계.

### 3단계 — 실제 셋업 (사용자 GO 후)

- 현재 멤버 4명(Admin/David/Matilda/Brandon)에 대해 `member/*` 브랜치 4개 생성·푸시.
- Admin/David/Matilda 3명에 대해 워크트리 생성. (Brandon은 메인 체크아웃에서 작업.)
- 워크트리 디렉토리 안내를 각 멤버 [identity/Will.md](../../) 에 추가 — 다음 세션의 그들이 어느 디렉토리에서 깨어나야 하는지 박아두기.
- main 브랜치 보호에 더해, **`dev`를 도입한다면** dev에도 같은 보호 적용 검토.

### 4단계 — 첫 머지 요청 사이클 검증

본인이 시범적으로 `member/Brandon` → `main` 머지 요청 메시지를 자기 자신에게 보내고 처리해서 워크플로 동작 확인. 또는 Admin/David/Matilda 중 한 명에게 작은 변경(자기 Memo 한 줄)을 부탁해 머지 사이클을 한 번 돌려본다.

## 주의

- **현재 미커밋 델타**가 워킹트리에 있습니다 — ONBOARDING의 §0.5 신설(이 규약 자체), END-OF-CONVERSATION 마커 섹션, CLAUDE.md 5번 단서, README.ai.md Phase D 갱신, Admin/Brandon inbox 메시지 일부. 이 변경들은 메인 체크아웃에서 발생했으니 워크트리 도입 전에 정리되어야 합니다.
  - **권장 순서:** (a) 미커밋 델타를 먼저 main에 한 번에 정리 커밋·푸시 (사용자 GO 필요), (b) 그 다음 워크트리·브랜치 구축. 그래야 깨끗한 main에서 분기 시작.
- 다른 멤버 워크트리 만들 때 **그들의 identity/Memo 변경분이 `member/<이름>`에 동기화**되어야 하는지 한 번 더 생각. 가장 단순한 답: 워크트리 생성 시점의 main HEAD가 모든 브랜치의 출발점이 됨. 이후 각자 자기 브랜치에서 자기 폴더만 수정.
